## قرارات التصميم قبل التنفيذ

1. **ملف المكتب ليس رقم دعوى**: البيانات المشتركة والتصنيف والقالب والوقائع والطلبات والمتابعة على `case_file`، أرقام كل درجة على `legal_case`. أول ملف أساسي في العلاقة هو سياق النزاع؛ الملفات الإضافية تبقى روابط متعددة.
2. **إضافتان علائقيتان ضروريتان فقط**: `procedural_stage` لغياب بديل مناسب، و`case_term` لربط الملف/الدرجة بقاموس موضوعات وكلمات متعددة قابلة للبحث والدمج دون قائمة نصية للأطراف أو الإجراءات.
3. **حفظ التفسير التاريخي**: قيم التخصص موزعة بأسماء الأنواع + لقطة تعريف القالب لكل نوع؛ تغيير النوع لا يمحو أي مساحة بيانات. اسم الجهة وقت المرحلة لقطة مستقلة عن الاسم الحالي.
4. **لا قواعد قانونية مفترضة**: كل مسار اختيار يدوي، والقوالب تقترح مجموعات عمل فقط؛ لا مراحل تلقائية، لا حساب طعن/تقادم، لا تقرير صلاحية طريق طعن. الاختيارات غير المدرجة تسجل كمسار يدوي مع مصدر الأوراق.
5. **إسقاط بحث مشتق في الجدول الحالي**: حقول تصفية ومؤشرات تشغيلية قابلة لإعادة البناء؛ لا مصدر حقيقة ثان. تحديث داخل معاملة الحفظ مع audit/outbox. تحسين تخصيص أرقام الإسقاط وصندوق التغييرات لتجنب قراءة كامل الجدول لكل كتابة.
6. **الفهارس**: نفحص EXPLAIN واستعلامات الصفحة قبل اعتماد مركبات؛ نوثق القياسات والفروق الفعلية بين المحركين ولا ندعي حجمًا لم نختبره.
7. **حماية الخصوصية**: لا فهرسة لملاحظات الأسرة/الأطفال الحساسة ضمن النص العام، ولا نظام صلاحيات موازٍ؛ التطبيق الحالي محلي بلا حسابات/صلاحيات متعددة ويجب بيان هذا القيد.
