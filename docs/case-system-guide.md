# مِداد 0.3 — دليل القضايا والمراحل والفهرسة المحلية

هذه توسعة للمستودع الحالي وليست برنامجًا أو قاعدة بيانات جديدة. الفرع `arena/da2efbff-law-office` غير مدمج وغير منشور. راجع [التقرير التنفيذي](case-system-report.md) و[القياسات الفعلية](case-system-performance.md) قبل تطبيقه على بيانات مكتب حقيقية.

## 1. قبل الترقية

- صدّر نسخة احتياطية من الإصدار الذي يعمل حاليًا، تحقّق منها، واحتفظ بها خارج مساحة الموقع في المتصفح. المرفقات الخارجية ليست جزءًا من محتوى النسخة المنطقية؛ احتفظ بملفاتها أيضًا.
- اختبر الترقية والاستعادة على نسخة منفصلة. لا تضع بيانات عملاء حقيقية في المستودع أو أدوات الاختبار.
- لا تمسح IndexedDB أو بيانات الموقع أو سجل الترحيلات لعلاج خطأ فتح أو مشكلة نشر.
- SQLite ينفّذ الترحيل الإضافي 2، ويستخدم آلية النسخ السابقة للترحيل عند ترقية ملف موجود. لا توجد لقطة احتياطية تلقائية مماثلة قبل ترقية IndexedDB؛ التصدير المسبق مسؤولية المشغّل.
- أغلق النوافذ الأخرى إذا ظهرت رسالة انتظار ترقية قاعدة البيانات. احتفظ بنافذة الترقية مفتوحة حتى اكتمال الفهرسة. تظهر أعداد السجلات المعالجة فعلًا، لا نسبة تقديرية.
- أصل التخزين مهم: لكل بروتوكول/مضيف/منفذ مساحة IndexedDB منفصلة. النقل بين أصلين يحتاج تصديرًا واستعادة، وليس نسخ عنوان الصفحة فقط.

## 2. ملف نزاع قبل القيد

من «القضايا» اختر «قضية / ملف جديد»:

1. اكتب عنوان الملف ونوعه وما تعرفه من الموضوع والوقائع والطلبات.
2. اترك بيانات المحكمة ورقم الدعوى فارغة إن لم تكن معلومة. الحفظ ينشئ ملف المكتب الحقيقي ورقمه الداخلي، لا رقم دعوى رسميًا مختلقًا.
3. اختر التصنيف الفرعي وطبيعة الدعوى إن كانا مناسبين للأوراق؛ القيم قابلة للإدارة وليست قائمة قانونية مغلقة.
4. أضف أطرافًا موجودين في دليل الأطراف، ثم حدّد صفة كل طرف وجانبه وهل يمثّله المكتب. صفة «موكل» وعلامة تمثيل المكتب ليستا الشيء نفسه.
5. أضف موضوعات وكلمات فهرسة ومراجع المستندات عند توافرها.
6. راجع قائمة الاستكمال. النقص الاختياري لا يمنع حفظ مسودة. الحفظ ليس شهادة بصحة المسار أو كفاية المستندات قانونًا.

قيمة المطالبة بالنزاع ليست أتعاب المكتب ولا تنشئ مديونية على العميل. الأتعاب والمدفوعات تبقى في المالية الحالية.

## 3. الأنواع والقوالب والتخصيص

- تظهر المجموعات المتخصصة بحسب النوع والتصنيف والاختيارات الشرطية. مثال: لا تظهر بيانات الأبناء الخاصة إلا عند بيان الحاجة إليها.
- تغيير النوع في ملف قائم يتطلب التأكيد. تبقى بيانات الأنواع السابقة محفوظة في مساحاتها، ويمكن الرجوع إليها.
- لقطة القالب وإصداره تحفظان مع الملف. تعديل قالب المكتب لا يعيد تفسير الملفات القديمة أو يمحو حقولها تلقائيًا.
- من «الإعدادات ← القضايا» يمكن إدارة القوالب والقيم المرجعية والتصنيفات والموضوعات والجهات والدوائر.
- تعديل تعريف القالب يحتاج إصدارًا أعلى ويخضع للتحقق. الخصوصية المضمنة لحقول الأطفال/المجموعات الحساسة حد أدنى: تغيير أعلام القالب لا يجعلها قابلة للفهرسة العامة.
- «تخصيص الأقسام» يستخدم تفضيلات الجهاز الحالية في `device_setting`. يمكنك تغيير الترتيب وطي الأقسام وإخفاء الاختياري. لا يمكن إخفاء العنوان والموضوع والنوع الأساسي بهذه الآلية. الإخفاء لا يحذف قيمة، ويُكشف الحقل المخفي إذا احتاج تصحيحًا عند التحقق.
- أعمدة جدول القضايا وفلاتره وعروضه المحفوظة تستخدم نظام الجدول والتفضيلات الموجود، لا إعدادات موازية.

## 4. المراحل والإجراءات المستقلة

في ملف المكتب، افتح «المراحل والإجراءات» ثم «تسجيل مرحلة»:

- سجّل التسوية أو مكتب العمل أو التظلم أو المحضر أو التحقيق أو أي إجراء آخر وفق الواقع.
- النوع «أخرى» يحتاج وصفًا فعليًا. سجل الجهة والمرجع والسنة والتواريخ والحالة والنتيجة ومصدر البيانات عند توافرها.
- التواريخ تنقل من الأوراق؛ تاريخ المتابعة اختيار مكتبي وليس ميعاد طعن أو تقادم محسوبًا.
- يمكن ربط مرحلة بمرحلة سابقة، مع منع ربطها بنفسها أو إنشاء دورة. لا يشترط وجود مرحلة سابقة.
- إغلاق مرحلة لا ينشئ مرحلة أخرى ولا دعوى. إنشاء الإجراء التالي أو الدعوى المرتبطة إجراء صريح من المستخدم.
- «متابعة المرحلة» تصل إلى نماذج المهام والمواعيد الحالية وتحتفظ بسياق الملف/الدعوى/المرحلة، وتعرض الأعمال المحفوظة.
- المستند المصدر وروابط المستندات تستخدم كيانات المستندات الحالية. لا توجد منظومة مرفقات ثانية.
- سجل تدقيق المرحلة قابل للبحث في الملخص والترقيم بصفحات وعدّ دقيق؛ لا يتوقف عند أول 200 حدث.

## 5. القيد والدرجات والطعون

- عند توافر قيد حقيقي، اختر إنشاء دعوى مرتبطة، ثم أدخل الرقم والسنة والجهة والدرجة كما في الأوراق.
- كل درجة أو دعوى مرتبطة سجل `legal_case` مستقل برقمها وتواريخها وأطرافها، مع استمرار ارتباطها بملف النزاع.
- أنشئ الدعوى التالية وعلاقتها يدويًا. لا يفترض التطبيق جواز الاستئناف أو النقض أو التظلم لكل نوع.
- علاقات الأبوة/التتابع تمنع الذات والدورات. العلاقات غير الهرمية لا تتحول إلى ترتيب إجباري.
- يمكن أن تختلف صفة الشخص وتمثيل المكتب بين الدرجات دون إنشاء شخص آخر. التعديل على طرف موروث في درجة لا ينبغي أن يغير بقية الدرجات؛ مسارات الحفظ تختبر هذا النطاق وتحفظ معرف العلاقة عند تعديلها.
- الجهات والدوائر لها سجل موحد وأسماء بديلة وتفعيل/تعطيل. يبقى اسم الجهة وقت المرحلة محفوظًا حتى بعد تعديل السجل المرجعي.

## 6. البحث والقاموس

- البحث محلي بالكامل ويطبّع الحروف والأرقام العربية المدعومة. الكلمات المتعددة تتقاطع بدل استبدال بعضها.
- اجمع البحث مع النوع والتصنيف والطبيعة والجهة والسنة والدرجة والحالة والمرحلة والأطراف والصفات والموضوعات والتواريخ ومؤشرات النقص والمتابعة وغيرها من الفلاتر الموجودة.
- العدد هو عدد النتائج المطابقة قبل ترقيم الصفحة، لا عدد أول مجموعة مرشحين. الملف المقيد لا يظهر مرة ثانية كملف غير مقيد.
- الموضوعات الهرمية والأسماء البديلة والكلمات والقيم اليدوية تستخدم القاموس والقوائم الموجودة. دمج مصطلحين يعيد ربط العلاقات ويتعامل مع التكرار، لا يدمج الأشخاص أو القضايا تلقائيًا.
- بيانات المجموعات الحساسة والملاحظات الخاصة لا تدخل الإسقاط العام. لا تكتب بيانات أطفال أو أسرارًا في عنوان عام/موضوع/كلمات مفتاحية إذا لم ترد ظهورها في البحث.
- الإحصاءات الدقيقة تحمل في الخلفية دون منع عرض الصفحة الأولى؛ علامة التحميل ليست رقم صفر مؤقتًا.
- بعض الفلاتر الواسعة في IndexedDB تحتاج فحصًا محليًا للسجلات المشتقة. قياس 100 ألف سجل ليس وعدًا بأن كل بحث أو جهاز سيكون فوريًا.

## 7. النسخ والاستعادة والتعافي

- التصدير والتحقق يشملان الإضافات والعلاقات والتدقيق. النسخة المنطقية حساسة وغير مشفرة تلقائيًا؛ تعامل معها كبيانات المكتب.
- نسخة v1 تتحقق وفق تعريف v1 الأصلي أولًا ثم ترفع منطقيًا إلى v2. معرفات السجلات وتاريخها لا يعاد توليدهما.
- عند الاستعادة بين المحركين تختلف دفاتر الترحيل الفنية. يحتفظ التطبيق بأصل دفتر المصدر في بيانات منشأ الاستعادة، ويثبت دفتر الهدف الصحيح؛ لا يغير ملفات ترحيلات v1 أو checksums الأصلية.
- استيراد السجلات معاملة ذرية؛ بناء الفهرس بعدها منفصل. إذا نجح الاستيراد وتعطل الفهرس، تعرض الواجهة أن السجلات استعيدت وأن الفهرسة معلقة، وليس أن البيانات لم تتغير. إعادة الفتح تعيد المحاولة وفق علامة الصيانة المحفوظة.
- بناء فهرس كبير قد يطول: في الاختبار الفعلي استغرق فتح مساحة 10 آلاف دعوى مع إعادة الفهرسة نحو 86 ثانية. لا تغلقه لمجرد تجاوز 20 ثانية.
- واجهات الصيانة البرمجية: `rebuildCaseIndex()` و`rebuildSearch()`؛ وأداة CLI الحالية `db:reindex`. لا يوجد ادعاء بمزامنة سحابية أو بمراجعة قانونية آلية.

## 8. تشغيل المطور والتحقق

يلزم Node.js 22.18 أو أحدث. اختبرت هذه الجولة Node.js 22.22.3 وChromium 153، لا كل المتصفحات والأجهزة.

```bash
npm ci
npm run typecheck
npm run typecheck:tests
npm test
npm run build:web
npm run test:ui:cases
npm run test:browser
npm run test:ui
npm run test:smoke   # يستخدم dist الناتج من البناء السابق
npm run db:check -- --db data/office.sqlite
```

لإعادة القياسات على بيانات اصطناعية مؤقتة فقط:

```bash
npm run db:bench:cases -- --engine=sqlite --count=10000
npm run db:bench:cases -- --engine=indexeddb --count=10000
npm run db:bench:cases -- --engine=sqlite --count=100000
npm run db:bench:cases -- --engine=indexeddb --count=100000
```

تستخدم الأدوات ملفات وقواعد وملفات تعريف متصفح اختبارية قابلة للاستبدال؛ لا تعِد توجيهها إلى قاعدة أو ملف تعريف شخصي حقيقي. لا ترفع `.arena/` أو `dist/` أو قواعد الاختبار إلى Git.

توليد المخطط الحالي: `npm run db:gen-portable` ثم `npm run db:gen-schema`. تعريفات v1 وبذورها وترحيلها الأول محفوظة لأجل التحقق والترقية؛ لا تولّد إصدارًا جديدًا بإعادة كتابة تلك الملفات.

## 9. مراجعة المكتب المطلوبة

قبل الاعتماد المهني، يراجع محامٍ مختص تصنيفات المكتب وأسماء الجهات والقوالب ومصادر الإجراءات والاختصاص وطريق الطعن في كل واقعة. لا يحسب النظام مواعيد قانونية، ولا يقرر وجوب التسوية أو مكتب العمل، ولا يستبدل مراجعة الأوراق. التشغيل محلي أحادي المساحة؛ شارة «خاص» ليست نظام حسابات وصلاحيات متعدد المستخدمين أو تشفيرًا للقرص.
