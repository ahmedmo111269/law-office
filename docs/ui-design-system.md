# نظام التصميم — مِداد

واجهة عربية RTL أصلية لإدارة مكتب محاماة مصري. هذا الملف هو المرجع المركزي لكل قيمة
بصرية ولكل مكوّن قابل لإعادة الاستخدام. لا تُكتب قيمة لون أو مسافة أو ظل خارج
`src/ui/tokens.css`؛ ولا يُعيد أي مكوّن تعريف شكل زر أو حقل بشكل مستقل.

## 1. المبادئ

| المبدأ | الترجمة العملية |
| --- | --- |
| RTL بالتصميم لا بالانعكاس | التخطيط يبدأ من اليمين: الشريط الجانبي يمينًا، الأيقونات قبل النص، «التالي» يشير يسارًا. لا يُستخدم `scaleX(-1)`. |
| العربية أولًا | IBM Plex Sans Arabic للنصوص والبيانات، Amiri للعناوين التحريرية. الأرقام والهواتف وأرقام الملفات داخل `dir="auto"`/`bdi` حتى لا تنقلب. |
| وضوح قانوني | مصطلحات قانونية دقيقة (مدعي، مدعى عليه، طعن، تنفيذ، إنابة). لا تلميحات تقنية في واجهة المستخدم. |
| البيانات مقدَّسة | لا تُعرض بيانات وهمية كأنها حقيقية. ما يظهر في الشاشة مأخوذ من `PortableLawOffice` عبر الخدمات. |
| لا قرار لوني وحده | كل حالة تحمل نصًا + أيقونة + لونًا، مع تباين ≥ 4.5:1. |
| هدوء بصري | خلفية رَقّية دافئة، أخضر قانوني للفعل الأساسي، نحاسي للتمييز، أحمر للخطر فقط. |

## 3. الخطوط

| الخط | الوزن | الاستخدام | المصدر |
| --- | --- | --- | --- |
| IBM Plex Sans Arabic | 400/500/600/700 | الواجهة والبيانات | `src/ui/fonts/ibm-plex-sans-arabic-*` (SIL OFL) |
| Amiri | 400/700 | عناوين تحريرية/غلاف التقارير | `src/ui/fonts/amiri-*` (SIL OFL) |

- 10 ملفات `woff2` محلية (476 KB)، تُحمَّل عبر `@font-face` نسبي في `base.css`؛ لا Google Fonts ولا CDN.
- مقياس: `--fs-2xs` 10 إلى `--fs-3xl` 40، مع `--user-font-scale` يضربه المستخدم من الإعدادات.
- ارتفاع السطر العربي 1.7–1.8 للنص الطويل، 1.4 للعناوين.

## 4. المسافات والاستدارة والظلال

- المسافات: مقياس 4px (`--sp-1` … `--sp-18`) حتى 72px. لا قيم عشوائية.
- الاستدارة: `--r-1` 6، `--r-2` 9، `--r-3` 14، `--r-4` 20، `--r-full` 999.
- الحدود: 1px بلون `--border` أو `--border-strong` للحقول.
- الظلال: `--shadow-1` للبطاقة، `--shadow-2` للقائمة، `--shadow-3` للحوار، `--shadow-4` للسحب.
- الارتفاعات: `--control-h` 36 / `--control-h-sm` 30 / `--control-h-lg` 42، صف الجدول 44/34/52 حسب الكثافة، الشريط الجانبي 268 (وضع الرصيف 76)، الشريط العلوي 62، شريط الجوال السفلي 60، `--content-max` 1560.
- الحركة: `--dur-1` 120ms، `--dur-2` 180ms، `--dur-3` 260ms مع `--ease`، وتُلغى كلها عند `prefers-reduced-motion`.

## 5. الهيكل والتنقل (IA)

```
مِداد
├── اليوم        مكتب اليوم · المهام والأعمال · المواعيد
├── العمل القانوني  الملفات · القضايا · الجلسات · الأحكام · أعمال التنفيذ · الإعلانات والإنابات
├── الأطراف والوثائق  العملاء · الأطراف والخصوم · المستندات · العقود والتوكيلات
├── إدارة المكتب   المالية · التقارير · الأرشيف · الإعدادات
└── عناصر دائمة   بحث شامل (Ctrl/⌘+K) · إضافة سريعة · الوضع الداكن · حالة التخزين
```

- 24 مسارًا فعليًا في `src/ui/main.ts`؛ كل وجهة في الشريط تفتح صفحة حقيقية.
- البحث الشامل فوق التطبيق (`Ctrl/⌘+K`، و`/` في الحقول غير النشطة) يبحث في فهرس `search_document` المحلي.
- الشريط الجانبي: 268px ≥1280، رصيف أيقونات 76px بين 1024–1279، درج منزلق <768.
- شريط سفلي بخمسة عناصر <768 مع «المزيد» لفتح الدرج.
- «إضافة» في الشريط العلوي تفتح قائمة إجراءات سريعة (ملف، عميل، مهمة، جلسة، مصروف…).
- حالة التخزين في تذييل الشريط تُظهر الاستهلاك الفعلي من `navigator.storage.estimate()` وتفتح نسخًا احتياطيًا.

## 6. المكتبة

`src/ui/components/` — 8 وحدات، كلها DOM مُنشأ عبر `h()` بدون `innerHTML`:

| المكوّن | الملف | ملاحظات |
| --- | --- | --- |
| الجدول المتقدم | `data-table.ts` | إظهار/إخفاء الأعمدة، سحب لإعادة الترتيب، تغيير العرض، تثبيت، كثافة، بحث، فلاتر، فرز متعدد، عروض محفوظة، ترقيم، تحديد جماعي، تصدير CSV، عرض بطاقات للجوال. |
| الحوار | `dialog.ts` | أحجام `sm/md/lg/xl/sheet`، حصر التركيز، Esc، إعادة التركيز، `confirmDialog`، `promptDialog`. |
| النماذج | `forms.ts` | `textField/selectField/dateField/textareaField/checkboxField` + أخطاء مرتبطة بـ`aria-describedby`. |
| المنتقي | `picker.ts` | بحث عن كيان (ملف/عميل/قضية) مع `aria-activedescendant` ولوحة نتائج. |
| القوائم | `menu.ts` | قائمة منبثقة بلوحة مفاتيح كاملة. |
| التنبيهات | `toast.ts` | `role=status/alert`، إغلاق يدوي، بلا أخبار نجاح قبل الحفظ. |
| الصفحة | `page.ts` | `pageHeader`، `sectionCard`، `emptyState`، `loadingRows`، `definitionList`، `timeline`. |
| حالة الجدول | `table-state.ts` | مخطط `TableState` + عروض محفوظة + `PAGE_SIZES`. |

كل المكوّنات تُبنى من `h()` في `src/ui/dom.ts` (نص لا HTML)، ما يمنع حقن HTML خامًا.

## 7. الصفحة القياسية

```html
<div class="page">
  <header class="page-head">
    <div class="page-head__main">
      <p class="eyebrow">…</p>
      <h1 class="page-title">…</h1>        <!-- قابل للتحرير في بعض الصفحات -->
      <p class="page-subtitle">…</p>
    </div>
    <div class="page-actions">…</div>
  </header>
  <div class="data-table">…</div>
</div>
```

- رأس الصفحة `flex` مع `flex: 1 1 320px` لمنع تمدد عنوان قابل للتحرير، و`outline:none` على `.page-title` أثناء التحرير.
- كل صفحة تمر بحالة تحميل (skeleton) ثم حالة فراغ موصوفة مع إجراء، ثم المحتوى.
- صفحة الملف (`/files/:id`) هي الصفحة المرجعية: هوية الملف، الأطراف، القضايا، الجلسات، الأحكام، المستندات، المالية، والنشاط في تخطيط `detail-layout` مع عمود جانبي.

## 8. الجداول المتقدمة

- `TableRequest { page, pageSize, search, filters, sortKey, sortDir }` → `TableResult { rows, total }`؛ التحميل صفحة بصفحة من الخدمة، لا تحميل كامل.
- `PAGE_SIZES = [10, 25, 50, 100]`، الافتراضي 25.
- التفضيلات (`hidden/order/widths/pinned/density/sort/search/filters/pageSize`) تُحفظ في `device_setting` بمفتاح `ui.table.<id>` — للجهاز، لا لقاعدة البيانات.
- عروض محفوظة لكل جدول (`ui.views.<id>`) مع تسمية وحذف.
- تثبيت الأعمدة يزيح تدريجيًا بالعرض الفعلي، والتحرير لا يفسد ارتفاع الصف.
- على الجوال يتحول الجدول إلى بطاقات (`.table-cards`) مع الإبقاء على كل الحقول الأساسية.

## 9. الحالات والتغذية الراجعة

| الحالة | التمثيل |
| --- | --- |
| تحميل | هياكل عظمية بارتفاع الصف (بلا قفز في التخطيط) |
| فراغ | أيقونة + عنوان + شرح + إجراء (لا صفحة بيضاء) |
| خطأ | بانر داخل الصفحة + زر إعادة محاولة + ظل الحوار يبقى إن كان الحفظ فاشلًا |
| نجاح | Toast بعد اكتمال الكتابة فقط، مع إمكانية التراجع عند الحذف |
| غير متصل | شارة `status-dot--offline` ونص واضح، دون أي تعطيل للكتابة المحلية |
| تركيز | حلقة `--focus-ring` بسماكة 3px على كل عنصر تفاعلي، لا تُحذف إلا لعنوان التحرير |

## 10. الوصول (WCAG 2.2 AA)

- HTML دلالي: `header/nav/main/aside/table/thead/th[scope]`، عنوان واحد `h1` لكل صفحة.
- كل حقل له `label` مرتبط، و`aria-describedby` للمساعدة والخطأ، و`aria-invalid` عند الفشل.
- كل زر أيقوني له `aria-label`، وكل صورة/أيقونة زخرفية `aria-hidden`.
- حصر التركيز داخل الحوار، وإعادته لمصدره عند الإغلاق، و`Esc` يغلق.
- تخطي إلى المحتوى الرئيسي موجود في `index.html` (وليس مرة ثانية في الهيكل المُنشأ).
- `prefers-reduced-motion` يلغي الحركات، و`forced-colors` يحافظ على الحدود، و`print` يخفي الشريط الجانبي والأدوات.
- اختبار آلي: 0 عنصر تفاعلي بلا اسم وصول في مسار الجلسة، وفحص تباين 30 زوجًا.

## 11. الأداء

- القراءة عبر `db.query()` مع `limit/offset` وفلاتر مفهرسة؛ لا `list()` كامل في أي جدول.
- البحث الشامل يستخدم `searchPage()` بحد 200 لكل دفعة، ثم يجلب الصفوف المطابقة فقط.
- تفاصيل الملف تحمّل الملخص ثم الأقسام الثقيلة (المالية/السجل) عند الطلب.
- حزم الصفحات منفصلة (`assets/chunks/*`) وتُحمَّل عند أول زيارة للمسار.
- Bundle أساسي: `app.js` 96 KB و`app.css` 68 KB (مضغوطين gzip أقل من ذلك)، والخطوط 476 KB كاملة محليًا.
- الحزم تُبنى بأسماء ثابتة (`app.js/app.css`) ليبقى فهرس Service Worker مستقرًا.

## 13. قواعد إلزامية

1. لا لون/مسافة/ظل خارج `tokens.css`.
2. لا `innerHTML` ولا حقن HTML من بيانات المستخدم.
3. لا نص نجاح قبل اكتمال الكتابة في قاعدة البيانات.
4. لا زر بلا وظيفة، ولا صفحة فارغة تُقدَّم كقسم مكتمل.
5. التخصيص (الأعمدة/الكثافة/الثيم/حجم الخط) لا يغيّر البيانات ولا يخفي معلومة حرجة.
6. كل كتابة تمر عبر الخدمات → `PortableLawOffice` → `DatabaseAdapter`.
